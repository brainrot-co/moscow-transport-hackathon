# Поправочные коэффициенты: как работает сейчас и что доделать

Состояние на 27.09.2026. Полное описание замысла для бэкенда и фронтенда — в `docs/corrections-spec.html`. Здесь — что из этого реально работает в коде и где ещё дыры.

## Коротко

| часть | статус |
|---|---|
| ML: эффекты факторов модели (`effects.parquet`) | ✅ работает, считается при каждом краткосрочном прогоне |
| ML: справочник факторов и сценариев (`reference/correction_factors.json`) | ❌ файла нет, есть только черновик схемы в спецификации |
| Бэкенд: хранение сценариев, применение поправок, предпросмотр, экспорт | ❌ не начато |
| Фронтенд: слайдеры, форма события, две линии на графике | ❌ не начато |
| Сценарные поправки (погода, ремонт, событие) | ❌ только описаны; значения по умолчанию — заглушки |

## Два вида поправок

1. **Фактор модели** — то, что модель уже учитывает: праздники и школьные каникулы. Слайдер меняет *силу* эффекта, который заложила модель: `k = 1` — как считает модель, `0` — без фактора, `2` — вдвое сильнее. Эффект считает ML.
2. **Сценарий** — то, чего модель не знает: ремонт, погода, мероприятие. Множитель на выбранные маршруты, даты и часы. Считает только бэкенд, ML не участвует.

Разделение нужно, чтобы не учесть праздник дважды: модель его уже заложила, и множитель «праздник −15%» поверх прогноза был бы двойным учётом.

## Что делает ML сейчас

Код: `ml/src/mtml/worker/effects.py`, вызывается из `worker/short.py` после проверок качества.

1. Основной прогноз строится как обычно.
2. Для каждого фактора, чьи признаки модель использует, берётся копия таблицы признаков, где **только на горизонте прогноза** фактор выключен (`neutralize`):
   - `holiday`: праздники, переносы, сокращённые и соседние с праздником дни становятся обычными днями по дню недели (`is_non_working` — только сб и вс, `day_type` — workday / saturday / sunday, близость к празднику — «далеко»);
   - `school_holiday`: флаги каникул обнуляются.

   История не меняется: модель по-прежнему «помнит», как праздники влияли в прошлом.
3. Та же обученная модель прогнозирует с изменёнными признаками (контрольный прогон). Веса не перезагружаются, признаки подменяются временно и возвращаются в `finally`.
4. По каждому маршруту и дню, где фактор что-то изменил:
   `log_effect = log(1 + сумма дня с фактором) − log(1 + сумма дня без фактора)`.
5. Результат пишется рядом с прогнозом: `runs/<run_id>/effects.parquet`.

| колонка | тип | смысл |
|---|---|---|
| `route` | int16 | маршрут |
| `date` | datetime | день |
| `factor` | str | `holiday` или `school_holiday` |
| `log_effect` | float64 | логарифм отношения «с фактором / без фактора» по дневным суммам |
| `yhat_without` | float64 | дневная сумма прогноза без фактора, для подписи «без праздника было бы …» |

В `meta.json` прогона есть поле `effects`: сколько дней затронул каждый фактор.

**Стоимость:** плюс два прогона модели, прогон вырос с 9 до 18 секунд.

## Как бэкенд должен применять (ещё не реализовано)

Для каждой строки прогноза маршрут × час после водяного знака:

```
yhat_adj = yhat
         × Π по факторам модели   exp(log_effect(route, date, factor) × (k − 1))
         × Π по сценариям         m,   если строка в области действия сценария
yhat_adj = max(yhat_adj, 0)
```

- Если строки эффекта на эту дату нет, множитель равен 1.
- Эффект дневной: один множитель на все часы дня.
- Квантили `q10` и `q90` умножаются на то же.
- Поправки применяются к часовым строкам **до** агрегации по дням и маршрутам.
- Факт (до водяного знака) не корректируется.

## Что получается на ноябре–декабре 2025

Прогон при «сейчас» = 01.11.2025 03:00, сумма по всем маршрутам:

| день | что за день | эффект праздника |
|---|---|---|
| 01.11 | рабочая сокращённая суббота | **+63%** к обычной субботе |
| 02.11 | воскресенье внутри блока 2–4 ноября | 0% |
| 03.11, 04.11 | праздники | **−56%**, **−55%** |
| 05.11 | первый день после праздников | −4% |
| 30.12 | предпраздничный | +2% |
| 31.12 | выходной | **−52%** |

04.11 по маршрутам — от −43% (17, 25) до −68% (50).

Каникулы: от −3% до +5%. Модель почти не учитывает их в ноябре–декабре, так что слайдер «каникулы» сейчас почти ничего не двигает.

Пример для 04.11, все маршруты: прогноз 107 тыс., без праздника 237 тыс. Слайдер `k = 0.5` даёт около 159 тыс., `k = 0` — 237 тыс.

## Известные ограничения и риски

1. **Один фактор `holiday` включает переносы.** Слайдер к 0 превращает рабочую субботу 01.11 в обычную субботу (−39%). Диспетчер может этого не ожидать. Вариант: отдельный фактор «переносы и сокращённые дни».
2. **Эффект — это мнение модели, а не правда.** Он показывает, сколько *модель* закладывает на праздник. Мы не проверяли, совпадает ли это с реальностью. Проверка: бэктест на майских праздниках и 12 июня (они есть в истории) — сравнить эффект модели с фактическим провалом.
3. **Разброс по маршрутам шумный** (−43…−68% в один и тот же праздник). Часть разброса реальна, часть — шум контрольного прогона. Можно сглаживать эффект к общему по всем маршрутам.
4. **Контрольный прогон сдвигает и другие дни.** В сумме это −0.24%, но выходные маршрута 50 (2–5 тыс. посадок, ремонт) сдвигаются до +96%. Эффекты хранятся только на днях фактора, так что на слайдеры это не влияет, но показывает, что модель на маленьких объёмах нестабильна.
5. **`k = 2` удваивает логарифм эффекта:** −55% превращается в −80%. Нужны разумные границы слайдера или ограничение результата.
6. **Эффекты пересчитываются каждой ночью** и могут немного меняться. Сохранённое диспетчером `k` остаётся, а величина эффекта под ним — из текущего прогона.
7. **Только краткосрочный горизонт.** У годового прогона эффектов нет.
8. **Двойной учёт сценариев.** Если событие уже идёт и есть в истории (маршрут 50 не ходит по выходным с сентября), модель его уже видит, и сценарий «×0.5» учтёт его второй раз. Бэкенд должен предупреждать, если на маршруте в последние недели был флаг `anomaly`.
9. **Окончание события множителем не лечится.** Модель рисует нули, пока ремонт в истории, а ноль ни на что не умножишь. Правильное решение — признак режима маршрута внутри модели.
10. **Значения по умолчанию для сценариев — заглушки.** Проверено только «сильный дождь −4%» (исследование по Берлину). Остальное экспертно. Для справки есть ridge-оценки по истории 2025 года: нерабочий день −36%, праздник в будний день сверх этого −15%, модульные каникулы −6%.

## Как посмотреть эффекты локально

```bash
export CLOCK_START=2025-11-01T03:00:00
uv run python -m mtml.worker once
```

```python
import json, pathlib
import numpy as np, pandas as pd

run = pathlib.Path("data/runs") / json.loads(pathlib.Path("data/active.json").read_text())["short"]
effects = pd.read_parquet(run / "effects.parquet")
effects["pct"] = (np.exp(effects["log_effect"]) - 1) * 100
print(effects.pivot_table(index="date", columns="factor", values="pct", aggfunc="median").round(1))
```
