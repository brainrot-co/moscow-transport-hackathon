# 1. ML-модель: артефакты, код обучения и инференса, запуск

## Что прогнозируем

Число посадок (успешных валидаций, `validation_result = 1`) на маршруте трамвая за час. 10 маршрутов: 1, 5, 7, 11, 12, 17, 25, 26, 28, 50. История — январь–октябрь 2025 года, прогноз — от водяного знака вперёд.

Метрика: WAPE-score = max(0, 1 − Σ|y − ŷ| / Σy).

## Результат

| что | WAPE-score |
|---|---|
| лидерборд, ноябрь–декабрь 2025 (лучший сабмит, ансамбль) | **0.88359** |
| лидерборд, одиночный Chronos-2 `cal_school_daytype` | 0.87989 |
| baseline организаторов | ≈ 0.48 |
| бэктест сен–окт 2025, 61 день (одиночный Chronos-2 с календарём и каникулами) | 0.885 |
| бэктест апр–июнь 2025, 61 день (то же) | 0.871 |
| реальная точность опубликованных прогонов (прогнозы от 01.09, 15.09, 01.10, 15.10, факт до 01.11) | 0.885–0.904 |
| годовой прогноз, бэктесты на 2–6 месяцев | 0.787–0.853 |

## Модель

Три горизонта из одного сервиса, бэкенд склеивает их в один ряд:

```
факт (до водяного знака) → краткосрочный прогноз (61 день) → годовой прогноз (до 365 дней)
```

### Краткосрочный прогноз (день, неделя, месяц): ансамбль на Chronos-2

[amazon/chronos-2](https://huggingface.co/amazon/chronos-2) — предобученная foundation-модель для временных рядов (120M параметров). Используется **zero-shot**: на наших данных не дообучается, получает историю и ковариаты в контексте. Дообучение LoRA пробовали, на 10 месяцах истории оно переобучается.

Ансамбль из трёх участников, прогноз — среднее:

| участник | как устроен |
|---|---|
| RH | Chronos-2, каждая пара «маршрут × час суток» — отдельный суточный ряд (9 × 24 = 216 рядов), ковариаты: производственный календарь + школьные каникулы |
| RHD | то же + тип дня (будни, сб, вс, праздник, рабочий выходной, пред- и послепраздничный) |
| V2 | прогноз суточной суммы маршрута (среднее недельного профиля и Chronos-2 по дневным суммам без ковариат и с календарём), раскладка по часам долями суточного профиля |

Почему «маршрут × час», а не один почасовой ряд: горизонт становится 61 шагом вместо 1 464, недельная сезонность остаётся внутри ряда. На бэктесте сен–окт без ковариат это 0.846 против 0.831 у почасового ряда. С календарём и каникулами — 0.885.

В сабмите 0.88359 у V2 был ещё один вариант с фактической погодой ноября–декабря из архива, то есть с «идеальным прогнозом погоды». В сервисе прогноза погоды нет, поэтому модель по умолчанию (`ensemble_cal_school_daytype_profile`) погоду не использует. Вариант с погодой доступен как `ensemble_cal_school_daytype_profile_wx`.

Квантили q10 и q90 — из Chronos-2, среднее по участникам, у которых они есть.

Схема ансамбля: [docs/img/ensemble.svg](../docs/img/ensemble.svg). История экспериментов и отвергнутые гипотезы: [docs/MODEL.md](../docs/MODEL.md).

### Годовой прогноз: сезонная регрессия

Chronos проверен только на горизонте 61 день, а проверить год на 10 месяцах истории нечем. Поэтому год строится объяснимой моделью, отдельно по каждому маршруту:

```
log(1 + дневная сумма) = уровень + эффект месяца + эффект типа дня + эффект каникул
```

- МНК по дням `final` без флага `anomaly`;
- уровень подтягивается к последним 8 неделям;
- часы — дневная сумма × суточный профиль вида дня;
- интервал — квантили остатков.

Прогон занимает 1.6 с. Подробно: [docs/year-forecast.md](../docs/year-forecast.md).

### Эффекты для поправочных коэффициентов

После основного прогноза воркер делает контрольные прогоны той же моделью с «выключенным» фактором на горизонте: праздники становятся обычными днями, каникулы обнуляются. Разница пишется в `effects.parquet`. Слайдер в интерфейсе масштабирует этот эффект: `yhat × exp(log_effect × (k − 1))`. Подробно: [docs/corrections-status.md](../docs/corrections-status.md).

## Артефакты

| артефакт | где |
|---|---|
| веса Chronos-2 | скачиваются с Hugging Face при сборке образа воркера и запекаются в него (`/opt/hf`, `HF_HUB_OFFLINE=1`). При работе сеть не нужна |
| стартовый прогноз (факты + пара прогонов short/year + справочники) | [`ml/seed/`](../ml/seed/), запечён в образ ingest |
| формат прогона | `runs/<run_id>/forecasts.parquet` (`route, ts, yhat, q10, q90`), `effects.parquet`, `meta.json` (модель, данные, проверки качества, маршруты без истории) |
| сабмиты на лидерборд | `ml/artifacts/runs/submission_*/` (`submission.csv`, `preds.parquet`, `summary.json`) |
| журнал экспериментов | MLflow (`ml/mlflow/`, локально): параметры, окна бэктеста, метрики по каждому запуску |

## Запуск

Нужны `uv` и распакованный `dataset.zip` в `dataset/` (`train.csv`, `test.csv`, `labels/`).

```bash
uv sync --group worker --group dev
```

**Бэктест** (контекст до `--cutoff`, оценка на `[cutoff, end]`):

```bash
uv run python ml/scripts/run_backtest.py ensemble_cal_school_daytype_profile --cutoff 2025-09-01 --end 2025-10-31
```

**Сабмит** на ноябрь–декабрь по всей истории:

```bash
uv run python ml/scripts/make_submission.py ensemble_cal_school_daytype_profile
```

**Инференс так же, как в сервисе** (факты на томе `data/`, прогноз публикуется в `data/runs/` и `data/active.json`):

```bash
uv run python -m mtml.ingest load dataset/train.csv dataset/test.csv
CLOCK_START=2025-11-01T03:00:00 uv run python -m mtml.worker once
```

**Через Docker** модель запускается сама: `make demo` или `make prod`, см. корневой README.

**Тесты:**

```bash
make test-ml
```
